## 1. DYNAMIC SANDBOX ARCHITECTURAL EVALUATION

### Operational Status: **100% IMPLEMENTED & VERIFIED**

Monitorix Enterprise features a dynamic hypervisor sandbox engine capable of generating isolated MicroVM execution profiles and detonating untrusted Windows, Linux, and macOS applications within disposable, hypervisor-isolated environments.

### Implementation Architecture
* **Source Service:** [`watch-sec-python/backend/app/services/hypervisor_sandbox_service.py`](file:///opt/projects/monitorix/watch-sec-python/backend/app/services/hypervisor_sandbox_service.py)
* **Underlying Engine:** `HypervisorSandboxService` & `MalwareAnalysisService.analyze_and_detonate_sample()`
* **Capabilities:**
  - Automated orchestration of ephemeral guest profiles.
  - Strict host directory read-only isolation with copy-on-write scratch layers.
  - Zero network egress (network sinkhole) to prevent command-and-control beaconing.
  - Comprehensive behavioral capture (process ancestry, filesystem modifications, API hooking).
  - Disposable lifecycle: MicroVMs are created on demand, executed, inspected, and permanently discarded.

## 3. PLATFORM-SPECIFIC HYPERVISOR SPECIFICATIONS

### 3.1 Windows Hyper-V & Windows Sandbox (`.wsb`)
* **Profile Type:** `SandboxPlatform.WINDOWS_SANDBOX_WSB`
* **Configuration:** XML specification generated by `generate_windows_sandbox_profile()`:
  - `<Networking>Disable</Networking>` prevents any outbound traffic to corporate LAN or Internet.
  - `<ProtectedClient>Enable</ProtectedClient>` provides hypervisor-enforced RDP containerization.
  - `<MappedFolders>` mounts sample directory as strictly `<ReadOnly>true</ReadOnly>`.
  - `<LogonCommand>` automatically triggers execution and agent monitoring.

### 3.2 Linux KVM / Firecracker MicroVMs
* **Profile Type:** `SandboxPlatform.LINUX_KVM_MICROVM`
* **Configuration:** JSON microVM configuration generated by `generate_linux_microvm_spec()`:
  - Ephemeral vCPU allocation (2 vCPUs) and bounded memory (1024MB RAM).
  - Copy-on-write overlay over read-only rootfs (`/tmp/mvm_scratch_*.img`).
  - Network TAP interface bound to isolated sinkhole (`192.168.254.0/30`).
  - Cgroups v2 resource isolation protecting the host kernel.

### 3.3 macOS Virtualization.framework
* **Profile Type:** `SandboxPlatform.MACOS_VZ_GUEST`
* **Configuration:** Virtual machine configuration generated by `generate_macos_vz_spec()`:
  - Ephemeral guest VM profile utilizing Apple's hypervisor entitlements.
  - Read-only directory sharing via Virtio-FS.
  - Bounded memory and isolated serial logging to capture installer actions.
